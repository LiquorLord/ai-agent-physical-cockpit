## 1. 总体概述与双系统哲学

AGY 物理级专属智能交互座舱在全志 V553 (sun8iw21) SoC 上实现了 **100% 物理级无损双系统**：
- **插入 MicroSD 卡**：系统启动定制的现代 AI 智能终端系统（具备免驱 USB 复合设备、1600x600 触控 UI 与边缘视觉识别）。
- **拔出 MicroSD 卡**：系统启动 **100% 原汁原味的原厂行车记录仪固件**（`cdr` 行车记录、无线 Apple CarPlay 与华为 HiCar）。

整个使用过程无需对板载 16MB SPI NOR Flash 进行任何侵入式修改。原厂固件完整无损。双系统的分支决策在冷启动时刻由硬件 BROM 自动判断完成。

## 2. 全志片上 BROM 硬件级启动优先级

全志 V553 (sun8iw21) 内部固化了只读 Boot ROM (BROM)，其硬件引导轮询顺序严格如下：

```
SDC0 (卡0 / MicroSD) ──> SPI NOR Flash (SPI0) ──> USB FEL 刷机模式
```

BROM 开机时首先扫描 **SDC0**：如果在 MicroSD 卡的 **第 16 扇区（偏移 8 KB 处）** 发现了合法的 **eGON 引导头**，BROM 会直接将镜像加载至 SRAM 并执行。
- **为什么是第 16 扇区？** 全志 BROM 固化的 eGON 签名检测地址硬编码在 SD 卡起始偏移 0x2000（8192 字节）处。这是芯片物理硅片层面的设计。
- **纯硬件级冷启动拦截：** 正因为 BROM 先检查 SDC0 再检查 SPI NOR，SD 卡可以 **完全越过** 原厂固件，板载 SPI Flash 甚至不需要被读取或执行。
- **结果：** 定制操作系统运行在完全独立的隔离环境中，拔卡即恢复原厂，真正做到物理级隔离。

## 3. 软件层双重保险回退机制

除了纯硬件 BROM 拦截外，系统还在板载 SPI Flash 的根文件系统中预置了双启动探测脚本作为双重保险：  
`/etc/init.d/S02sdboot`

脚本核心执行逻辑：

```bash
# S02sdboot – 双系统无损引导探测脚本
if [ -b /dev/mmcblk0p1 ]; then
    # 检测到 MicroSD 卡第 1 分区存在
    mount /dev/mmcblk0p1 /mnt/sdcard
    if [ -x /mnt/sdcard/init_usb_monitor.sh ]; then
        # 将控制权完全移交给 SD 卡上的自定义初始化脚本
        exec /mnt/sdcard/init_usb_monitor.sh
    fi
fi
# 若未插入 SD 卡或脚本不存在，则继续原厂启动流程
# (S70app / cdr 正常运行)
```

- **设备探测：** 脚本探测 `/dev/mmcblk0p1` 设备节点。
- **控制权移交：** 若检测到 SD 卡中的 `init_usb_monitor.sh` 脚本，则使用 `exec` 替换进程树，阻断原厂 `S70app` (`cdr`) 启动。
- **安全保障：** 拔出 SD 卡后，脚本自然跳过移交分支，原厂行车记录仪正常加载。

## 4. MicroSD 卡分区与文件系统设计

MicroSD 卡采用精简的高性能单分区布局：

| **偏移** | **大小**       | **内容**                     |
|------------|----------------|---------------------------------|
| 0x0000     | 8 KB           | MBR 分区表                      |
| 0x2000     | 8 KB           | 扇区 16：eGON 引导头 (SyterKit / U-Boot SPL) |
| 0x100000   | 剩余空间       | 第 1 分区：Ext4 文件系统 (`/mnt/sdcard`) |

**文件系统格式化规范：**
- **文件系统**：Ext4（通用兼容 Linux 4.9 与 6.x）。
- **关键参数**：**禁用** `64bit` 属性（`-O ^64bit`）。避免 64 位 inode 导致 32 位嵌入式用户态工具链（如 uClibc/Busybox）发生溢出与段错误。
- **挂载参数**：`noatime, nodiscard, data=ordered`。

## 5. 硬件看门狗管理机制

全志 V553 集成了 `sun8i-wdt` 硬件看门狗。原厂固件配置为若 60 秒内未被喂狗则触发芯片级硬件复位。在定制系统运行期间，必须持续喂狗以保证系统稳定：

**多层喂狗方案：**
1. **用户态守护进程**：`init_usb_monitor.sh` 启动后台喂狗进程：
   ```bash
   ( while true; do echo 1 > /dev/watchdog 2>/dev/null; sleep 3; done ) &
   ```
2. **应用集成**：核心接收程序（如 `fb_receiver`）在事件循环中主动向 `/dev/watchdog` 写入保持信号。
3. **安全回退**：若定制系统出现严重死锁，看门狗将在 60 秒后自动复位系统，保障设备不挂死。

## 6. 开源极客体验与零风险承诺

AGY 物理级专属智能交互座舱遵循 **零焊接、零刷机风险** 的极客原则：

- **无硬件改装**：只需一张 MicroSD 卡插入机身卡槽。
- **无需刷写主板**：原厂 16MB SPI NOR Flash 完整保留。
- **拔卡瞬间恢复**：只要拔出 MicroSD 卡，设备立刻变回行车记录仪。
- **社区承诺**：“插卡即是全新 AI 座舱，拔卡即是原装行车记录，不拆机、不飞线、零风险”。
